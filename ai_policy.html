Use of generative AI in contributions

This page sets out how we handle contributions to X-PSI that were developed with the help of generative AI tools, such as large language models (LLMs) and AI coding assistants. It applies to everything submitted to the X-PSI repositories: code, tests, documentation, tutorials and notebooks, issues, pull requests and review comments.

We do not ban the use of AI tools. Many of us use them, and they can be genuinely useful for exploring code, debugging, and drafting tests or documentation. However, reviewing a contribution takes the time of the X-PSI team, and X-PSI is used for published scientific results. We therefore ask that every contribution is worth more to the project than the effort needed to review it, and that it is clear how it was produced.

Human responsibility

  • You are responsible for everything you submit, whether you wrote it yourself or an AI tool generated some or all of it.

  • You must have read, understood and tested all of it before asking anyone to review it, and you must be able to explain any part of it during review.

  • Respond to reviewers yourself. Passing reviewer comments to an AI tool and posting its answers back does not count as engaging with the review.

  • Write pull request descriptions, issues and review comments yourself, so that they reflect your own understanding. Using tools to translate or to correct grammar and spelling is fine.

Disclosure

The description of every pull request must include an AI disclosure, including pull requests where no AI tools were used. If AI tools were used, state:

  • which tool(s) and model(s), including the version where it is available (for example “Claude Code with Claude Opus 5.5”);

  • how they were used (for example: writing new code, writing tests, writing documentation, debugging, refactoring, or understanding existing code); and

  • which parts of the code or text were generated by AI, and how you checked them.

You can copy the following into your pull request description and fill it in:

## AI disclosure

- AI tools used: <none | tool(s) and model(s), with version>
- Used for: <e.g. writing code, writing tests, documentation, debugging,
  understanding the code base>
- AI-generated parts and how I checked them: <files/sections, and how you
  reviewed and tested them>
- I have read, understood and tested all AI-generated content, and I opened
  this pull request myself.

You may also record AI assistance in your commit messages with a trailer such as Assisted-by: <tool>:<model>. Please do not list an AI tool as a co-author (Co-authored-by:): authorship and responsibility for a contribution rest with its human contributors. Some tools add a Co-authored-by: line to commit messages automatically, so please check your commits and replace it with Assisted-by:. An automatic check on every pull request flags commits that list an AI tool as co-author or author, and explains how to fix them.

Disclosure is not held against you. It helps reviewers decide where to look most carefully, keeps a record of how X-PSI was developed, and helps people who use X-PSI in publications to meet the disclosure requirements of journals and funders.

Licensing and copyright

X-PSI is distributed under the GNU General Public License v3. By submitting a contribution you confirm that you have the right to contribute it under that licence. AI tools can reproduce existing code or text, so it is your responsibility to make sure that AI-generated material does not infringe anyone else’s copyright or licence terms.

Automated contributions and bots

Every contribution must come from a human who has reviewed it and takes responsibility for it.

  • We do not accept issues, pull requests or review comments created autonomously by AI agents or other automated tools. Such submissions will be closed without review, and accounts that repeatedly submit them may be blocked.

  • The only exceptions are automated workflows that the X-PSI team has set up itself. These are listed below; any new ones will be added to this list.

Automated workflows currently enabled by the X-PSI team:

  • GitHub Actions (acting as github-actions[bot]), configured in .github/workflows/. It runs the test suite on every pull request and on main, and checks that each pull request has a changelog fragment and that none of its commits lists an AI tool as co-author or author. It also writes to the repository in two cases: it commits the updated CHANGELOG.rst to a pull request’s branch when a maintainer adds the ready-for-changelog label, and it deploys the documentation to the gh-pages branch after each change to main. It does not open issues or pull requests.

Use by the X-PSI team

The same rules apply to X-PSI team members. Maintainers may also use AI tools to help with triage or review, but decisions on contributions are always made by people.

Enforcement

  • Pull requests whose description does not include an AI disclosure will be marked as drafts and will not be reviewed until one is added.

  • Contributions that do not follow this policy, or that we judge to be low-effort AI-generated content, may be closed without detailed review.

  • Repeatedly ignoring this policy may be treated as a breach of our Code of Conduct.

This policy will be revised as tools and community practice develop. If you are unsure whether or how it applies to your contribution, please ask us via the GitHub Issues page before opening a pull request.

Acknowledgements

This policy draws on the policies of other open-source scientific software projects, in particular:

  • Astropy, Usage of Generative AI (human accountability, engaging with reviewers yourself, autonomous agents are not contributors);

  • SunPy, AI Usage (a mandatory disclosure section in every pull request, and how it is enforced);

  • NumPy, AI Policy, and SciPy, AI Policy (disclosing which tools were used, how, and for which parts);

  • earthaccess, AI Policy (disclosing tool versions, and no autonomous agent pull requests);

  • scikit-learn, Automated Contributions Policy (refusing contributions generated by fully automated tools);

  • LLVM, AI Tool Use Policy (the principle that a contribution should be worth more to the project than the time it takes to review it);

  • the Scientific Python Development Guide (the Assisted-by: commit trailer, and keeping AI tools out of Co-authored-by:).
